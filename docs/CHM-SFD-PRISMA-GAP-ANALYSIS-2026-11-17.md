فرع الأساس الذي تمت مراجعته: `chm-source-extracted`

> هذا التقرير مبني على قراءة الملفات الحالية في GitHub. لا يعني أن التعديلات أو قاعدة Neon قد نُفذت. لا توجد migrations مطبقة من خلال هذا العمل.

## 1. الحالة الحالية المثبتة

### Prisma
يحتوي `prisma/schema.prisma` في فرع `chm-source-extracted` على سبعة نماذج فقط:
- `User`
- `ComplaintOperation`
- `FieldAwareness`
- `FieldBox`
- `BoxOpeningMinute`
- `InventoryItem`
- `AuditLog`

### تخزين الواجهة
ملف `lib/store.tsx`:
- يحمّل بيانات أولية من `lib/data/seed`.
- يقرأ ويكتب بيانات المستخدمين والعمليات والأنشطة والصناديق والتحليلات والمتابعة والمخزون في `localStorage`.
- ينشئ جلسة الواجهة بتخزين اسم المستخدم في `localStorage`.
- يتحقق من كلمة المرور في المتصفح بمقارنة مباشرة مع قيمة المستخدم.
- لا يظهر في الملف مسار API يرسل جميع عمليات التعديل إلى قاعدة البيانات.

### طبقة API
ملف `lib/data.ts` يوفر مسار Prisma لبعض عمليات الشكاوى في API، لكنه يسمح بمخزن ذاكرة في التطوير عند غياب قاعدة البيانات، ويرفض ذلك في Production. هذا لا ينقل تلقائياً عمليات `StoreProvider` القديمة إلى PostgreSQL.

### المصادقة
ملف `lib/auth.ts` يهيئ Better Auth باستخدام اتصال قاعدة بيانات منفصل. يجب التحقق من جداول Better Auth ومواءمة حسابات المستخدمين والصلاحيات قبل اعتماد تسجيل الدخول النهائي. لا يجوز اعتبار وجود جداول المصادقة دليلاً على ترحيل بيانات المستخدمين التشغيلية.

## 2. فجوات المخطط مقابل قالب التشغيل

| المجال في القالب | الوضع في Prisma الحالي | المطلوب قبل الاعتماد |
|---|---|---|
| مرجع المشاريع | حقول رقم/اسم مشروع نصية داخل بعض النماذج | جدول مرجعي مستقل، مفتاح مصدر، تحديث upsert، حالة أرشفة |
| مرجع المواقع | حقول نصية للمحافظة والمديرية والعزلة والقرية | جداول/علاقات متدرجة، مفاتيح ثابتة، منع فقدان التاريخ |
| مرجع التصنيفات | أسماء نصية داخل العملية | تصنيف هرمي بثلاثة مستويات |
| العمليات | `ComplaintOperation` جزئي | مواءمة جميع أعمدة ورقة العمليات، الفرع، المنشئ، المحرر، حقول الإحالة والرد والإغلاق |
| المعنيون بالرد | غير موجود كنموذج مستقل | Responder وربطه بالفرع والإحالات |
| سجل الإحالات | غير موجود | Referral متعدد السجلات لكل عملية |
| سجل المتابعة | غير موجود كنموذج مستقل | OperationFollowUp / timeline |
| التحليل والإجراءات | غير موجود | Analysis وCorrectiveAction مع المسؤول والاستحقاق والتحقق |
| الإدارة الميدانية | `FieldAwareness` جزئي | FieldActivity وعلاقات أيام النشاط والحضور والتوعية والتوزيعات |
| أعضاء اللجنة/فريق المشروع | غير موجودين | جداول أطفال منفصلة أو جدول موحد مع نوع العضوية وحالة الحضور |
| تفاصيل أيام التوعية والمستفيدون | غير موجودة | AwarenessDay وBeneficiaryAwareness |
| الملصقات والبرشورات ودفتر المحاضر | غير موجودة | سجلات تسليم/استخدام/استرجاع مرتبطة بالنشاط والمخزون |
| صناديق الشكاوى | `FieldBox` جزئي | حقول القالب كاملة وعلاقات المشروع/الموقع/النشاط |
| محاضر فتح الصناديق | `BoxOpeningMinute` جزئي | كل أعمدة المحضر، تواريخ فعلية، عدادات مفصلة، مرفقات، علاقة بالصندوق |
| المخزون | `InventoryItem` رصيد ثابت | InventoryMovement كحركات توريد/صرف/استخدام/إرجاع وتسوية، مع احتساب الرصيد |
| طلبات المخزون | غير موجودة | InventoryRequest وموافقات وتسليم |
| المتابعة والتقييم | غير موجودة | MonitoringEvaluation وسجل الزيارات والتوصيات |
| المستخدمون | `User` أساسي | أدوار وصلاحيات وعضوية فرع، وربط آمن مع Better Auth |
| إعدادات النظام | غير موجودة | SystemSetting مع صلاحيات تعديل |
| سجل التدقيق | `AuditLog` مقيد بعملية | سجل عام للكيانات، قيم قبل/بعد، مستخدم وفرع ووقت |
| الرسائل النصية | غير موجود | MessageLog وحالة المزود |
| المرفقات | رابط مفرد/حقول متفرقة | Attachment عام متعدد الارتباطات مع metadata وحالة |
| سجل الاستيراد | غير موجود | DataImportBatch مع المقبول والمرفوض والأخطاء والبصمة |
| تكامل MIS | غير موجود | MISIntegrationLog ومؤشر المزامنة |

## 3. مشكلات تصميم يجب معالجتها في اقتراح Prisma

1. نموذج `ComplaintOperation` الحالي لا يحتوي حقل فرع صريحاً، ما يمنع فرض عزل الفروع على مستوى الاستعلامات بطريقة موثوقة.
2. ربط المشروع والموقع والتصنيف نصي في العملية؛ يلزم إضافة علاقات مرجعية مع الاحتفاظ بلقطة نصية عند الحاجة للسجل التاريخي.
3. لا يوجد `createdById` و`updatedById` موحدان في النماذج التشغيلية.
4. `InventoryItem` يخزن كميات الرصيد مباشرة؛ القالب يتطلب حركات مخزون قابلة للتتبع.
5. `AuditLog.operationId` إلزامي ومحدود بالعملية، بينما القالب يسجل أحداثاً على أنواع متعددة من السجلات.
6. تواريخ بعض النماذج مخزنة كنصوص؛ يجب تحديد الأعمدة التي تمثل تاريخاً/وقتاً فعلياً وفق محتوى Excel وقواعد الاستخدام.
7. يجب منع أي API من إعادة كلمات المرور أو أسرار الجلسات، وعدم استيراد عمود كلمة المرور من Excel قبل إثبات أنه hash صالح ومتوافق.

## 4. تصميم مقترح للمرحلة التالية

### مراجع البيانات
- `ReferenceProject`: مفتاح خارجي فريد `projectNumber`، وحقول المصدر، `sourceUpdatedAt`، `isActive`.
- `ReferenceLocation`: شجرة ذات `parentId` و`level` مع `sourceKey`؛ أو جداول مستقلة إذا أثبتت البيانات أن ذلك أوضح.
- `ReferenceClassification`: شجرة ذات `parentId` و`level` مع ترتيب العرض.

### التشغيل
- `ComplaintOperation` مع `branchId` و`createdById` و`updatedById` وروابط المراجع.
- `Responder`, `Referral`, `OperationFollowUp`, `Analysis`, `CorrectiveAction`.
- `FieldActivity` والجداول التابعة للحضور وأيام التوعية والمستفيدين والتوزيعات.
- `FieldBox`, `BoxOpeningMinute` مع العلاقات والحقول المكتملة.
- `InventoryMovement`, `InventoryRequest`.
- `MonitoringEvaluation`, `Attachment`, `MessageLog`, `DataImportBatch`, `MISIntegrationLog`.
- `SystemSetting`, `AuditLog`, وربط User/Branch/Role/Permission.

هذه أسماء تصميمية مقترحة وليست أسماء جداول منشأة حالياً.
